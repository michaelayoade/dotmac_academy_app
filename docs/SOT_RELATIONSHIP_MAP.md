# Dotmac Academy source-of-truth relationship map

This map names the canonical owner for each business decision, derived field,
external consequence, and repair path. Routes, templates, CLI commands, timers,
and SMTP are adapters around these owners.

| Domain/state | Authoritative input and owner | Canonical writer | Derived/projection state | Reconciler/backstop |
|---|---|---|---|---|
| Academy deployment identity | Sole offline-created `Tenant` row plus `TENANCY=single` topology | Offline bootstrap owns identity; kernel startup owns binding | `request.state.tenant` | Startup rejects zero/multiple tenants; resolver rejects any slug other than the database-owned binding; RLS fails closed |
| User identity and roles | `Person`, `UserCredential`, `Role`, `PersonRole` | Account/lifecycle services | Auth sessions and navigation permissions | Tenant-bound token/session checks; admin invitation workflow |
| Login abuse state | Credential failure count and `locked_until` | `web_auth.authenticate` | Login response | Credential row lock and successful-login reset |
| Applicant intake | Public `/apply` facts | `admissions.submit_application` | Applicant profile completeness and display `program` | Idempotent email-key intake; admin review for legacy gaps |
| Curriculum placement | Active `Track` + `CohortTrack` | Public canonical selection or audited `assign_applicant_intake` | `Applicant.track_id`, `Enrollment.track_id`, `program` snapshot | Composite FKs; acceptance/enrolment gate; admin placement correction |
| Admissions decision | Applicant facts, assessment validity, configured threshold | `admissions.transition_applicant` / `apply_assessment_policy` | Current applicant status | `AuditEvent` transition ledger; admin detail history |
| Entrance assessment time | Server `assessment_started_at` | `entrance_exam.start_exam` | Elapsed snapshot, remaining time, exceeded flag | Server wall-clock recomputation; admin reset |
| Entrance assessment result | Canonical question bank and submitted answers | `entrance_exam.grade_and_record` | Score, level, competency profile, validity | Applicant row lock; single-sitting guard |
| Learner assessment attempts | Activity policy, canonical person/activity rows | `assessment.submit_activity`, `attempts.open_or_create_attempt` | Best score, completion | Person row locks; unique attempt/open-sitting constraints |
| Course completion/certificate | Best scores and completion rules | Completion service | Completion record and certificate | Idempotent recomputation; certificate outbox attachment generation |
| Email consequence | Committed domain transaction | `email_outbox.enqueue_email` | Pending/sent/failed delivery ledger | Timer worker, exponential retries, stable Message-ID, manual requeue |
| SMTP delivery | One outbox row | `email_outbox.deliver_pending` | `sent_at`, sanitized error class, invite delivery projection | `academy-email-outbox.timer`; SMTP is transport only |
| Academy settings | Environment defaults plus `platform_settings` overrides | Academy admin settings route using restricted settings-writer role | Effective SMTP/branding/policy/lab config | DB-over-env resolver; blank secret fields preserve existing value |
| Application runtime | `app.assembly` product declaration | `dotmac_kernel.create_app` | FastAPI app, lifespan, tenancy binding, generic middleware and liveness | Architecture tests forbid a parallel app factory and copied middleware |
| Official operational history | Domain service facts | `write_audit_event` | Admin audit and applicant decision history | Migration baseline plus append-only application behavior |
| Student reminder consequence | Canonical enrollment/deadline/session/grade/completion state + `ReminderPreference` | `reminders.sweep` (sole decision owner; ledger `ReminderLog` enforces once-per-occurrence) | In-app notification + outbox email (immediate/digest/quiet-hours pacing) | `academy-reminders.timer` re-sweeps idempotently; admin history + audited resend; outbox stays delivery owner |
| Public catalog visibility | `Course.listed` + `status='published'` (ADR 0003) | Course import/authoring services | Anonymous landing and `/courses` projection | `catalog.public_catalog` is the only reader; routes add no extra filters; external marketing pages are 301 redirects, never copies |
| Lab instructions rendering | Filesystem `instructions.md` imported via `lab_content.import_labs()` | `LabTemplate.instructions_md` — the canonical Markdown source; `instructions_html` is retained only as a fallback for templates that predate this field | Per-instance HTML via `lab_content.render_instance_instructions()`: `{{key}}` seed placeholders are interpolated against that instance's `LabInstance.seed` before rendering through `authoring.render_markdown()` (shared sanitization/embed pipeline) | Re-import bumps `LabTemplate.version` via `source_hash`, which now covers the raw Markdown; `instructions_md IS NULL` falls back to the legacy pre-rendered `instructions_html` rather than failing |
| Lab runtime ownership | Tenant-scoped web requests recorded as queued `lab_operations` intents | `academy-labs` worker running as live-verified non-owning `academy_lab_worker` through lab-host-only `LAB_WORKER_DATABASE_URL` with `LAB_HOST_ROLE=lab`; `app_admin` remains migrations/offline maintenance; worker is sole writer of `LabInstance` runtime state and sole caller of containerlab/check execution | `LabInstance.status`, `runtime_presence`, consoles, errors, lease/settlement fields, and lab `Submission`/`Score` rows | Partial unique open-operation index; short priority-ordered `SKIP LOCKED` claims; process-incarnation settlement fence; bounded external commands plus phase/check-boundary lease refresh; global/per-tenant advisory-lock capacity admission; kind-specific leases and attempt ceilings; `lab-reconcile` repairs expired/pre-cutover operations, cross-checks `containerlab inspect --all` against database state, destroys rowless Academy runtimes, and sweeps lab-host console drift; a host-wide, non-blocking, crash-safe `fcntl.flock` (`app/services/host_lock.py`) serializes every containerlab-invoking call between the continuous worker and `lab-reconcile` — contention defers/requeues the worker's operation and lets the reconciler skip that pass cleanly rather than raising, never held across a database row lock; `LabInstance.instance_name` is derived from the instance's own id (`dal-<uuid>`) and enforced globally unique at the database (not tenant-scoped, since containerlab's runtime namespace on a lab host is host-global), so the name a request creates can never collide with another tenant's runtime; `runtime_presence` (`absent`/`present`/`unknown`) is a worker-owned field independent of `status` — capacity accounting counts `present`+`unknown` regardless of lifecycle `status`, so an escalated instance whose runtime may still be running is neither silently released back into the capacity pool nor treated as safe to reap consoles for; deploying this column's migration requires a synchronized worker restart, since an old worker never sets it and a row left at its default is invisible to reconciliation; every containerlab/docker/ssh subprocess the worker starts runs in its own process group (`start_new_session=True`) and a timeout, cancellation, or shutdown tears down the whole group (SIGTERM, bounded grace, then SIGKILL) via `_run_contained` in `app/services/labengine/containerlab.py`, backstopped at the systemd level by `KillMode=control-group`/`TimeoutStopSec=30s`/`SendSIGKILL=yes` on `academy-lab-worker.service` — signal propagation through the real host's `sudo -n containerlab` invocation still depends on that host's sudoers/session configuration and requires manual verification there, not provable from this repo's tests alone; a separate whole-process-lifetime singleton lock (`worker_singleton_lock`, a different lock file from the per-operation `host_lock`) is acquired once at worker startup before any database session or reclaim/drain work, so a second worker process (a manual invocation racing systemd, or two systemd instances) fails fast instead of both later contending on every containerlab call — the reconciler does not acquire this lock and continues to contend only on the per-operation lock; `lab_operations.claimed_host`/`claimed_epoch` (migration `0059_lab_claim_owner`) are a structural decomposition of `claimed_by`'s existing fencing identity, written alongside it on every claim but never themselves compared in any fencing predicate (`claimed_by` alone remains the sole value `heartbeat`/settlement checks); immediately after acquiring the singleton lock and before its ordinary poll loop, a worker runs a one-shot `reclaim_previous_epoch` scan (its blocking `FOR UPDATE` bounded by an explicit `lock_timeout` so a conflicting lock cannot hang the whole worker's startup indefinitely) that requeues, WITHOUT refunding any attempt, any under-ceiling row this same host claimed under a previous (crashed/replaced) process epoch — identical to `reconcile_stuck`'s own under-ceiling requeue's attempt accounting — but a matched row already at its kind's attempt ceiling is instead marked "failed" (with automatic-destroy escalation where applicable), via the exact same shared ceiling-check helper `reconcile_stuck` uses, so a worker that repeatedly crashes before ever settling a claim correctly accumulates toward and eventually hits the attempt ceiling instead of being unconditionally forgiven on every restart; recovering its own prior incarnation's under-ceiling claims immediately at restart rather than waiting out the ordinary lease, while a claim with a different host or with null/legacy structural ownership (a pre-0059 worker, or one predating this migration) is left untouched and still recovered only by `reconcile_stuck`'s ordinary lease-expiry path; ttyd consoles are spawned as ordinary children of the worker process itself (not through `_run_contained`'s containment), so any worker stop/restart already kills every running console via the same cgroup-wide `KillMode=control-group` behavior (systemd's own default, in effect before this work too) — `sweep_orphan_consoles` only deletes stale console entries for no-longer-live instances and has no path that detects and recreates a still-active instance's dead console, so a learner's browser console for any active Linux lab is silently broken until reset/redeploy; a known, pre-existing limitation this work does not change, tracked as follow-up debt, not fixed here; `lab_operations.origin`/`runtime_precondition` (migration `0060_lab_conditional_ops`) let `reconcile_runtime`'s two repair branches (`db_only_repairs` enqueueing `kind="destroy", origin="runtime_cleanup", runtime_precondition="present"`; `missing_runtime` enqueueing `kind="deploy", origin="runtime_repair", runtime_precondition="absent"`) express repair INTENT without asserting the repaired OUTCOME — the reconciler no longer projects `status`/`error`/`runtime_presence` onto the instance itself for either branch (including the prior-error `missing_runtime` sub-case, which now goes through the same conditional `enqueue()` instead of settling directly), and an enqueue race is resolved by comparing the FULL `(kind, origin, runtime_precondition)` tuple, not `kind` alone, before a pass may claim its own intent won; only the worker's own locked, authoritative recheck may settle the outcome, via `ContainerlabEngine.deploy_if_absent`/`destroy_if_present` (`app/services/labengine/containerlab.py`), which perform the precondition observation and the containerlab mutation atomically inside exactly ONE `host_lock` acquisition — never by composing the already-locked public `inventory()`/`deploy()`/`destroy()` methods, which would reopen the exact race this design exists to close; `app/services/lab_lifecycle.py`'s `provision_if_absent`/`destroy_if_present` enforce the load-bearing ordering invariant an earlier, unauthorized, quarantined attempt at this same slice got wrong: locked precondition check -> conditional containerlab mutation (only if the precondition holds) -> console teardown (only if a mutation actually occurred) -> console recreation/final projection — a precondition mismatch for a conditional DESTROY settles as a successful no-op strictly BEFORE `stop_consoles`/`engine.destroy`/any mutation can run, never after; a conditional DEPLOY's "runtime present" outcome is handled differently and unconditionally, never by preserving whatever `consoles`/`status` the row already has — a conditional ("runtime_repair") deploy's own target instance is, by construction, one `reconcile_runtime`'s `missing_runtime` branch flagged specifically because its lifecycle `status` said active/provisioning/resetting while its RUNTIME WAS MISSING, so it routinely already carries NON-EMPTY, STALE `consoles` from before that runtime disappeared — there is no realistic "genuinely different, still-valid concurrent deploy" case to protect for this specific operation kind (the partial unique open-operation index already guarantees at most one open operation per instance), so `lab_lifecycle._rebuild_consoles_from_live_inspection` ALWAYS stops whatever consoles are currently recorded (safe and harmless even if already stale/dead/empty — `stop_consoles` matches live local processes by instance id, not by trusting the DB row) and then resyncs from a REAL, fresh, locked `engine.inspect_running()` call — never a redeploy — converging to the exact same end state a normal successful deploy would reach; both places a conditional deploy can observe "present" — `run_claimed`'s cheap preliminary check (`engine.status()`, `lab_lifecycle.resync_present_preliminary`, which fully settles the outcome WITHOUT ever calling `deploy_if_absent`) and `provision_if_absent`'s own `deploy_if_absent`-returns-`None` mismatch (the authoritative, lock-protected recheck that still catches a race the preliminary check missed) — apply this identical unconditional resync, so neither path is a bare trust-and-skip of stale row data; `ContainerlabEngine.inspect_running` mirrors `_destroy_unlocked`'s own topology-path ownership check (a `lab_name` match alone is not proof of ownership) and returns `None` — treated as "not found", setting `runtime_presence="unknown"` and leaving `status`/`error` untouched — rather than raising, since this is a read-only resync helper, not a destructive one; `HostLockUnavailable` during a conditional operation is safe to restore to the instance's exact pre-operation state (more precise than the ordinary destroy-then-deploy path's own conservative handling, which must assume an unproven partial mutation since it is two separate engine calls) because the single conditional primitive's one lock acquisition guarantees nothing was mutated if it fails; migration `0060`'s downgrade refuses (via a bounded-`lock_timeout`, `ACCESS EXCLUSIVE`-locked check) when any `queued`/`claimed` row still carries a non-null `runtime_precondition`, so an old (pre-0060) worker can never misinterpret a live conditional intent as an unconditional operation |
| Learning observations | Meaningful learner actions at their owning services' commit points | `learning_events.record` (append-only; INSERT-only grants) | Learner activity + cohort insight projections (`insights.py`) | Savepoint-isolated `emit` — ledger failure never breaks the owner; consequences stay with reminders/queue owners |
| Learner intervention state | Deterministic rules over ledger + canonical records | `success_queue.sweep` / `success_queue.transition` | Success Queue page, queue CSVs, weekly digest attachments | Idempotent sweep refresh + auto-resolve when a rule stops firing; audited lifecycle |
| Segment messaging consequence | Instructor action on a deterministic segment | `success_queue.message_segment` | In-app notifications + outbox rows | Audited action id; outbox idempotency per action+person; delivery stays with the outbox worker |
| Stranded-learner reactivation | Active student enrolment with no `UserCredential` and no `AuthSession` ever | `reengagement.reinvite_stranded` (owns *who is locked out*; token minting stays `lifecycle._issue_token`) | Fresh `AccountToken(kind='invite')` + `account_invite` outbox row | Re-runnable — a new token supersedes the stale link that stranded them; never an at-risk rule, which stays `success_queue.sweep` |
| Admin activity reporting | Canonical pipeline records, learning-event ledger, open Success Queue | `admin_reports.send_activity_report` | Daily admin email (engagement rates, top movers, attention list) | Read-only projection — re-derives no threshold; a wrong queue is wrong here too, by design |
| Learning state for staff and external learners (ADR 0004) | Academy curriculum, enrolment, activity, assessment, completion | This Academy — sole LMS; `dotmac_erp`'s `training_course`/`lesson`/`assessment` tree is non-authoritative | ERP `TrainingCourseAssignment` + `EmployeeCertification` projections | Webhook projection is idempotent and rebuildable from Academy state; unmatched identity must fail loudly, never record a false success |
| Employment, training requirement and credential state (ADR 0004) | ERP `Employee`, department/manager, assigned training | `dotmac_erp` | Academy `Enrollment.audience` + `employee_ref` supplied at enrolment | Identity is the employee reference, never a lowercased email match |
| Presentation contract (ADR 0006) | `dotmac-ui` UI contract 1 token names, preset and compiled asset | `dotmac-ui`; Academy writes only product values in `src/input.css` | Academy CSS and full-page `<link>` elements | `test_dotmac_ui_adoption.py` ratchets pin, mount, templates, palette/contrast and compiled output; CI rebuild catches drift |

## Adapter rules

- Public and admin web routes validate input, call the owning service, and
  render its result. They do not duplicate transition or delivery policy.
- API routes require a tenant-bound authenticated admin for management data.
  Public intake exists only at `/apply`.
- CLI commands do not print raw invite, reset, assessment, or onboarding
  tokens. They request a queued consequence and report counts.
- Email templates and SMTP do not decide business outcomes.
- Imported identifiers, display strings, cached elapsed values, and current
  status alone are not authoritative substitutes for their owning records.

## Authority changes

Any future move to multi-customer hosting, a different admissions owner, an
external LMS decision engine, or an external notification control plane must
name the old and new owner, shadow verification, cutover gate, drift repair,
fallback retirement, and boundary tests in an ADR before cutover.
