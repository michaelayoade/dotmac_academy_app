# Apple HIG adaptation audit — Dotmac Academy

**Audit date:** 2026-10-06  
**Platform interpretation:** Responsive education/productivity web application used primarily in desktop and mobile browsers. Native-only HIG capabilities such as haptics, Dynamic Island, App Store metadata, and macOS menu-bar commands are not applicable.  
**Scope:** All 73 Jinja templates, the authenticated application shell, public pages, form journeys, chapter/coursework UI, all 16 data tables, shared pagination, and both CSS bundles.

## Bottom line

**Post-remediation score: 93/100 — release ready.** The measurable HIG checker scores **100/100 with no violations** across 18 distinct shared target types and 13 semantic color pairings. No button, route, field, column, or data value was removed.

The remaining seven points are not known defects: five are native-platform capabilities that do not exist in a browser application, and two require final hands-on VoiceOver/Safari verification rather than static proof.

## Measurable audit

### Baseline failures

- Shared buttons, fields, menu controls, search, and notifications rendered at 40×40px.
- Pagination and rows-per-page controls rendered at 32×32px.
- Disabled pagination text used #919b91 on white: **2.88:1**.
- The HIG checker correctly rejected both target sizes and the contrast pairing.

### Final result

The Apple HIG skill checker evaluated every distinct shared interactive primitive: primary, ghost and secondary buttons; fields; menu, area and sidebar navigation; notification and account controls; pagination; public CTAs; carousel controls; chapter/subtopic navigation; checkbox rows; and FAQ disclosures. It also evaluated every semantic foreground/background pairing used by the shared palettes.

## Findings and completed remediation

### Visual design

- Preserved the approved Dotmac logo, forest/sage palette, Domine/Hanken typography, square-soft geometry, content density, and all existing information.
- Added higher-contrast token behavior for prefers-contrast: more and Windows forced-colors mode.
- Added solid alternatives for translucent navigation, lightbox, scrim, and carousel-label surfaces when reduced transparency is requested.
- Kept the existing restrained motion language and disabled nonessential animation/scroll behavior for reduced-motion users.

### Navigation and structure

- Added a keyboard-visible “Skip to main content” link to the authenticated shell and every standalone/public page.
- Corrected nested main landmarks in chapter and course-preview pages so each document has one main content landmark.
- Added Command+K and Ctrl+K search focus with aria-keyshortcuts.
- Retained the mobile drawer’s focus trap, Escape dismissal, inert background, and focus restoration.
- Named every horizontally scrollable table/course region and made it keyboard focusable.

### Accessibility

- Raised shared controls from 32–40px to at least 44×44px while preserving compact visual glyphs.
- Raised public carousel dots and course-row arrows to 44×44px.
- Made chapter, subtopic, FAQ, account, secondary, and custom buttons meet the same target.
- Added a consistent 2px visible focus ring with 3px offset to links, buttons, summaries, and custom controls.
- Added scope="col" to all table headers and an accessible label for visually blank action headers.
- Added an explicit label to the profile-photo input and the search-results field.
- Added appropriate autofill purposes for applicant/enrollee/profile identity fields.
- Exposed unread notification count in the notification control’s accessible name.
- Added polite atomic live regions for HTMX results and busy state during requests.
- Exposed the assessment countdown as a non-chatty timer.
- Ensured status is expressed with visible text as well as color.

### Interaction and feedback

- Preserved every form, button, route, table column, pagination control, and data field.
- Added busy cursors and aria-busy during HTMX requests.
- Kept the public carousel from advancing while pointer-hovered or keyboard-focused.
- Exposed carousel position and selected controls to assistive technology.
- Made public horizontal course rows keyboard focusable and reduced-motion aware.
- Made hidden code-copy controls visible when keyboard focused.

### Responsive and data-heavy pages

- All 16 tables retain every column and use horizontal scrolling instead of hiding data.
- Small-screen table instructions remain sticky and visible.
- Pagination controls remain complete and are now large enough to operate accurately.
- Text remains browser-scalable; fixed control heights were replaced by minimum heights where text can grow.
