# Prepared coherent onboarding source

This capsule is incremental SOURCE ONLY. It is not an application installation,
qualified runtime, released owner, completed audit migration, or permission to
activate. No local imports, tests, typing, SQL, builds, installs, Docker, or
network-shell commands were run. The permitted evidence is source comparison,
stdlib AST/hash checks, and the SHA-pinned Ruff executable.

`finish_onboarding_step` proves the persisted tenant-qualified portal bearer in a
separate private operation. Existing principals lock in UUID order before the
Applicant and complete Task set. It refreshes the bearer, exact-email resolution,
linked identity and intake after waits, refuses drift, and never discovers and
locks a replacement existing Party after Applicant. Completing the route's Task
precedes automatic eligibility, including enrolled, rejected, missing-cohort,
incomplete-checklist, and absent-key cases. Repeat completion timestamps and
admin pending/done changes after enrollment remain supported.

The operation uses canonical storage facts to create/reuse an exact-email
identity, genuine Learning admission enrollment to preserve existing
role/status/audience while updating track, the single Applicant transition
implementation, configured additive global grants, complete credential membership,
and shared private invitation mechanics. Any credential alias suppresses password
setup. Existing identity names, activation, profile/preferences/avatar, custom
Party fields and unrelated grants are checked for preservation. Creation composes
the sealed initial-identity policy only for a new identity. Public completion and
explicit administrative enrollment share the guarded enrollment decision; admin
enrollment does not add an automatic global role or invitation.

Welcome enqueue executes inside the operation's yield/savepoint. False is ordinary
success; a real failure rolls back Task, identity, Learning, Applicant, grants,
tokens, audits and outbox. Post-enqueue flush/revalidation checks Session/root and
private instance bindings, bearer/resolution, Task membership/state, identity,
role catalog/grants, credentials, invitation/sibling effects and actual audit
rows. Refusal is propagated only after the same root is recovered without the
rollback-required latch. Private state and material references clear on exit.

The new automatic branch uses the approved attribution only after genuine bearer
proof: system / onboarding / no actor Party / dotmac_academy_app. It writes actual
`applicant.transition` and `account.invitation.completed` events through the
public Kernel audit API and verifies persisted fields. Public source strings,
absent actor IDs, copied contexts and ORM rows cannot select that branch.
`admissions_declarations.py` declares the transition action once. The assembly
owner must compose this declaration and the existing invitation declaration.
Legacy admin and assessment auditing is isolated behind a lazy historical helper;
it is not silently converted to system attribution.

All new business defaults live in Settings/env: enrollment role, invitation
replacement policy, and the ordered supported three-procedure seed catalog.
Settings reads are strict DB-over-env. Null/malformed/store failures refuse.
Seed labels/order affect new rows and the ordered admin Task API; existing Task
rows are never relabeled/reordered/reset. The captured portal template uses fixed
procedure cards and ignores stored labels/order. This policy does not configure
portal presentation.

Hosted tests are authored, NOT RUN. They cover genuine persisted bearer flow,
rotation/cross-tenant refusal, task-first repeated/missing steps, exact canonical
reuse and exact-miss uniqueness, custom grants/any alias, new initial state and
in-flight policy pinning, natural independent-connection races, system audit
attribution, copied/source-string refusal, per-stage and per-owned-flush failures
followed by actual outer commit, and composed CSRF/ordinary/HTMX browser behavior.
The browser password test consumes the actual queued onboarding invitation and
does not mint a legacy replacement. A concurrent first-identity completion that
observed no Party refuses when resolution changes during its Applicant wait;
a fresh retry succeeds as a task-only repeat without acquiring a late Party lock.

Original onboarding, entrance-exam, portal and automatic-acceptance scenarios
remain present, including the complete zero-admin end-to-end regression without
skip masking. Its earlier assessment-origin transitions and ordinary admin
success still require separate canonical audit bridges. Captured `tests/conftest.py`
retains legacy `api_actor`/assembly lineage and is read-only; root owns canonical
whole-fixture conversion. These prerequisites are not claimed green here.
