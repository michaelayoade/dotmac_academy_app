# LabInstance.status (app/models/lab.py) itself has exactly two owners:
# lab_operations.py is the worker's operation-settlement code
# (queue/start/reset/deploy/error transitions), lab_lifecycle.py is
# provision/destroy/reap. Every other entry below writes a DIFFERENT
# model's `.status` (Enrollment, EmailOutbox, SuccessQueueEntry, Person,
# CourseOffering-adjacent records, ...) — listed here because the scan is
# honestly file-wide, not because they touch LabInstance.
#
# This is a RATCHET, both directions. See
# tests/architecture/test_lab_instance_status_writers.py:
#   * a write in a file not listed here fails the build;
#   * a listed file's count rising fails the build;
#   * a listed file's count falling (or the file disappearing) without this
#     file being updated to match also fails the build — the list only
#     shrinks, and it must shrink for real, on record.
#
# Do not regenerate this file to make a failure go away. A new entry means a
# new file assigning some model's `.status`, LabInstance's included, and
# that always deserves a human look before it is added here deliberately.
