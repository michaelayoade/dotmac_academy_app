# Per-entry-point-family reach of the eager `dotmac_kernel.db` reference
# runtime, as of the 2026-09-09 runtime-readiness inventory
# (docs/2026-09-09-eager-reference-runtime-readiness-inventory.md).
#
# This is a RATCHET, not a gate, and it is DELIBERATELY two-directional: see
# test_eager_reference_runtime_reach.py for why a silent DECREASE is treated
# as seriously as an increase. A count landing at zero across every family
# does not mean the eager reference runtime stopped executing — it may only
# mean the remaining reach moved somewhere this file's families don't cover,
# or that a genuine Kernel runtime-composition seam retired it (in which case
# this file must be edited in the SAME change, with the inventory doc
# updated to say why).
#
# Format: <family>:direct=<N>:transitive=<yes|no>
#
# direct   — files in this family's own file list that contain a top-level
#            `import dotmac_kernel.db` / `from dotmac_kernel.db import ...`
#            / `from dotmac_kernel import db` statement (AST-detected).
# transitive — whether importing this family's representative entry module,
#            in a fresh subprocess, results in `dotmac_kernel.db` appearing
#            in `sys.modules` afterward. A family with direct > 0 is always
#            transitive=yes (the direct import alone guarantees it); the
#            interesting case is a family with direct=0 that is still
#            transitive=yes, which is exactly the "grep found nothing but the
#            eager engine still built" defect this ratchet exists to catch.
boot:direct=0:transitive=yes
api_deps:direct=1:transitive=yes
cli:direct=1:transitive=yes
web:direct=2:transitive=yes
scripts_tasks:direct=0:transitive=no
